## (архів) первісний план чек-інів

**Суть:** тренер вмикає обраним клієнтам щоденний вечірній чек-ін («Розкажи про сьогоднішній стан…») + авто-чек-ін після тренування («Як пройшло? Запиши голосове»). Клієнт відповідає ГОЛОСОВИМ боту в TG → транскрипція → сумаризація за шаблоном → тренеру в адмінку: саммарі + оригінальне аудіо (прослухати).

**Архітектура (план):**
1. **Вхідні повідомлення бота** — НОВЕ: зараз боти лише шлють. ### 8.2 АРХІТЕКТУРА (як в'яжемо — рішення)

### 8.3 ДОМЕН — брейншторм (рішення відкрите, схиляюсь до варіанту A+B)
Питання користувача: один домен чи персональні? Чи не скажуть тренери «що це за домен»?
- **Клієнти доменів майже НЕ бачать** — вони живуть у Telegram-боті (бот = повністю бренд тренера; URL-бар у Mini App прихований). Тож для КЛІЄНТІВ персоналізація вже вирішена ботом + лого/accent у застосунку. Окремі домени клієнтам не потрібні.
- **Тренер (адмінка)** бачить домен при логіні. Варіанти:
  - **A (дефолт):** один спільний домен (напр. `admin.<продукт>.com` + `app.<продукт>.com`). Після логіну — його лого/accent. Найпростіше, миттєвий онбординг.
  - **B (upgrade):** піддомен на тренера — `x_slug.<продукт>.com` (Cloudflare wildcard + Pages). Slug авто-визначає бренд, «відчувається своїм». Автоматизується через CF API при онбордингу.
  - **C (premium white-label):** власний домен тренера (`grekfit.com`) через Cloudflare custom domain. Найбіліше «своє», але тренер має володіти доменом + налаштувати DNS. Пропонувати як платну опцію.
- **Рекомендація:** старт = **A** (спільний домен) + брендинг ботом та в UI; **B** як легкий upgrade; **C** для тих, хто хоче повний white-label. Цінність персоналізації НЕ страждає, бо її несе бот + інтерфейс, а не домен.
