# Інструкція: як розгорнути TRAINER і переконатися, що він працює

Написано для людини, не для машини. Кроки виконуються по порядку.
Кожна команда — окремим рядком, її можна скопіювати й вставити в Термінал.

Якщо десь застряг — унизу є розділ **«Коли щось пішло не так»**.

---

## Що це за проєкт

Платформа для персональних тренерів. Дві частини:

- **Кабінет тренера** — клієнти, програми, календар, оплати. Працює і з
  телефона, і з комп'ютера.
- **Застосунок клієнта** — Telegram Mini App: тренування, харчування, звіти,
  прогрес.

Обидві частини — це по одному файлу `index.html`, у якому лежить усе одразу.
Ніякої «збірки» немає: відкрив файл — бачиш увесь застосунок.

## Частина 1. Запустити на своєму комп'ютері з нуля

### Крок 1. Перевір, чи є Node.js

```bash
node --version
```

Має вивести щось на кшталт `v22.x.x`. Якщо пише «command not found» —
постав Node.js із **nodejs.org** (кнопка LTS) і повтори.

### Крок 2. Забери проєкт із GitHub

```bash
git clone git@github.com:olegoliyar-cmd/trainer.git
```

Отримаєш теку `trainer`. Зайди в неї:

```bash
cd trainer
```

> **Якщо git скаржиться на доступ** — значить твій комп'ютер ще не
> «представлений» GitHub. Це окрема історія з ключем; найпростіше — скачати
> проєкт кнопкою **Code → Download ZIP** на сторінці репозиторію.

### Крок 3. Запусти

```bash
node dev-server.mjs
```

У відповідь побачиш приблизно таке:

```
DEV server on http://localhost:3210
  client  → http://localhost:3210/
  trainer → http://localhost:3210/trainer/
  api     → http://localhost:3210/api/trainers
```

⚠️ **Дивись на номер порту у виводі, а не запам'ятовуй 3210.** Якщо порт
зайнятий, сервер візьме інший, і адреса буде інша. На цьому вже двічі
губився час.

### Крок 4. Відкрий у браузері

| Адреса | Що побачиш |
|---|---|
| `http://localhost:3210/` | перемикач: клієнт на телефоні / тренер на телефоні / тренер у вебі |
| `http://localhost:3210/trainer/` | кабінет тренера напряму |
| `http://localhost:3210/index.html` | застосунок клієнта напряму |

Дані тут **несправжні** — це локальна «пісочниця» з демо-клієнтами
(Вася, Оксана і т.д.). Псувати їх не страшно, вони лежать у
`backend/data.json`.

**Щоб зупинити сервер** — натисни `Ctrl+C` у тому вікні Термінала.

## Частина 2. Перевірити, що воно справді працює

Тут дві перевірки. Перша — швидка, «чи все на місці». Друга — головна,
«чи працює сам продукт».

### Перевірка 1: чи нічого не зламалося

```bash
node scripts/health_check.mjs
```

Займає ~15 секунд, нічого не змінює. Має закінчитись рядком:

```
🟢 Усе зелене (56 перевірок).
```

Що вона стереже:

| Група | Що ловить |
|---|---|
| **Відбитки** | файл зник · файл змінився · файл переїхав (побайтово) |
| **Секрети** | паролі й ключі в тому, що піде на GitHub |
| **Архів на диску** | `archive/` не в git, тож більше ніхто його не стереже |
| **Запускові шляхи** | усе, на що вказує конфіг, існує |
| **Асети** | кожне посилання в HTML веде на реальний файл |
| **Синтаксис JS** | увесь код парситься без помилок |
| **Живий прогін** | піднімає сервер і смикає 7 адрес |

> Якщо ти **навмисно** щось міняв, вона почервоніє на «вміст не змінено».
> Це нормально. Скажи їй, що новий стан правильний:
> ```bash
> node scripts/health_check.mjs --save-baseline
> ```

### Перевірка 2: чи працює сам продукт (головна)

```bash
node scripts/e2e_program_flow.mjs
```

Це не «сторінка відкрилась». Тест проходить **весь шлях продукту** і на
кожному кроці звіряє зміст:

1. тренер складає програму (2 дні, 3 вправи)
2. заводить клієнта й призначає йому цю програму
3. **клієнт відкриває застосунок** — чи бачить саме цю програму, чи ті самі
   вправи, чи ті самі підходи
4. **клієнт виконує тренування** — 80кг×8, 80кг×8, 82.5кг×6
5. **тренер відкриває кабінет** — чи бачить це тренування, з тією ж вагою

Має закінчитись так:

```
🟢 НАСКРІЗНИЙ СЦЕНАРІЙ ПРОЙДЕНО: 19 перевірок за 0.3с
```

Тест сам робить резервну копію локальної бази й повертає її в кінці —
твої демо-дані не постраждають. Останній рядок «mock-базу повернуто
побайтово» це підтверджує.

### Чому цим тестам можна вірити

Зелений тест, який ніколи не падав, нічого не доводить. Тому обидва тести
навмисно ламали й перевіряли, що вони це помічають:

| Що ламали | Чи спіймав |
|---|---|
| програма не доїжджає до клієнта | ✅ «клієнт бачить: нічого» |
| у програмі губиться другий день | ✅ «днів: 1, очікувалось 2» |
| у підходах губиться вага | ✅ показав `[{"reps":8}]` замість ваги |
| тренер не бачить тренувань | ✅ «підходи не збігаються» |
| клієнт не активується | ✅ «було invited → стало invited» |
| зник файл проєкту | ✅ «ЗНИК ВМІСТ» |
| у код підкинули пароль | ✅ вказав файл і рядок |
| зник шматок архіву | ✅ «4262 файлів замість 5373» |

Після кожного ламання все повертали назад і звіряли побайтово.

## Частина 3. Де що лежить

```
trainer/
├── apps/client/      застосунок клієнта (Telegram Mini App)
├── apps/trainer/     кабінет тренера (телефон + комп'ютер)
├── supabase/         справжній бекенд: база + серверні функції
├── backend/          «пісочниця» для локальної роботи
├── scripts/          перевірки (ті два тести вище)
├── docs/             документація і плани
└── archive/          НЕ цей проєкт (старий GrekFit) — на GitHub не їде
```

⚠️ **`archive/` існує тільки на твоєму комп'ютері.** Його свідомо не заливали
на GitHub: там 431 МБ і чужі паролі від GrekFit, через які GitHub блокував
заливку. Якщо диск помре — архів зникне. Живий проєкт це не зачіпає.

## Частина 4. Де він живе, крім твого комп'ютера

Правки завжди йдуть в один бік:

```
твій комп'ютер  →  GitHub  →  сервер
```

**GitHub:** `github.com/olegoliyar-cmd/trainer`
Резервна копія всієї історії. Щоб відправити свої зміни туди:

```bash
git add -A
git commit -m "коротко, що змінив"
git push
```

**Сервер Hetzner:** тека `/opt/trainer`
Дзеркало, яке саме підтягує свіже з GitHub кожні 15 хвилин.

```bash
ssh -i ~/.ssh/openclaw_hetzner root@178.104.84.6
```

Уже на сервері:

```bash
trainer-update
```

— підтягнути негайно, не чекаючи 15 хвилин.

```bash
systemctl status trainer-update.timer
```

— подивитись, чи автооновлення живе.

> **Із сервера нічого не запушиш** — і це навмисно. Ключ доступу там лише на
> читання. Сервер — це копія, а не друге робоче місце. Якщо його зламають,
> у твій репозиторій нічого не запишуть.
>
> Паролів і ключів на сервері **немає** свідомо, тому деплої звідти не
> робляться.

## Частина 5. Викотити в продакшен

Обидва застосунки живуть на Cloudflare Pages. Ключі беруться з файлу
`.dev-secrets.env`, який лежить у корені й **ніколи не потрапляє в git**.

**Перед деплоєм обов'язково:**

```bash
node scripts/health_check.mjs
node scripts/e2e_program_flow.mjs
```

Обидва мають бути зелені. Червоне — не деплоїмо, розбираємось.

| Що | Куди | Що складати в бандл |
|---|---|---|
| Кабінет тренера | `traineros-admin.pages.dev` | `apps/trainer/index.html`, `apps/trainer/super.html`, `supabase/data-store.supabase.js`, `backend/exercises.json` |
| Застосунок клієнта | `traineros-app.pages.dev` | усе з `apps/client/` крім `dev/`, плюс `supabase/data-store.client.js` і `data-store.js` |

```bash
npx wrangler@3 pages deploy <тека> --project-name=<проєкт> --branch=main --commit-dirty=true
```

🔴 **Для клієнтського застосунку обов'язково збільш кеш-бастер** `?b=mtbNN` на
одиницю. Інакше телефони покажуть стару версію, і ти витратиш годину на
пошук неіснуючого бага.

Після деплою переконайся, що сторінка `/super` у тренера досі відповідає —
її легко зачепити ненароком.

## Коли щось пішло не так

**«command not found: node»**
Node.js не встановлений. Візьми з nodejs.org, кнопка LTS.

**Сторінка не відкривається**
Найчастіше — дивишся не на той порт. Подивись, який номер сервер надрукував
при запуску, і використай саме його.

**«port already in use»**
Попередній сервер ще живий. Знайди його:
```bash
lsof -i :3210
```
і зупини за номером процесу (колонка PID):
```bash
kill <номер>
```
Не гаси процеси за назвою через `pkill` — так можна ненароком убити щось
чуже, включно з власним підключенням до сервера.

**Лінійка червона на «вміст не змінено»**
Ти щось міняв. Якщо навмисно — `node scripts/health_check.mjs --save-baseline`.
Якщо ні — подивись, які файли вона назвала, і поверни їх:
```bash
git checkout -- <файл>
```

**Лінійка червона на «Секрети»**
У код потрапив пароль або ключ. Вона покаже файл і рядок (саме значення не
друкує навмисно). Прибери його з файлу, а значення поклади в
`.dev-secrets.env`.

**E2E впав**
Він назве конкретний крок — наприклад «клієнт бачить: нічого». Це означає,
що зламався саме той шматок ланцюжка. Шукай у `backend/store.mjs` функцію,
яка за нього відповідає.

**Треба відкотитись до стану перед великим прибиранням**
```bash
git checkout before-cleanup-2026-08-15
```
Це мітка на стані від 15.08.2026. Щоб повернутись назад:
```bash
git checkout main
```

**Усе зламалось, хочу чисту копію**
Просто забери проєкт із GitHub заново в іншу теку:
```bash
git clone git@github.com:olegoliyar-cmd/trainer.git trainer-new
```
Твоя стара тека лишиться недоторканою.

## Що варто зробити колись

Це не терміново, але записано, щоб не забулось:

- **Ротувати ключі GrekFit** — у `SECRETS-LOCAL.md` записані значення, які
  ми прибрали з документації 15.08.2026. Вони можуть бути ще живі.
- **Прибрати демо-клієнтів із продакшену** — Андрій, Соломія, Тарас, Марта
  у тренера Романа. Перед реальним запуском їх там бути не має.
- **Крони рахують час як UTC+3.** Взимку зсунуться на годину.
- **Клієнтський застосунок у проді старіший за твій диск** — там немає фікса
  проти зуму. Рішення від 15.08.2026: не чіпати, поки не наведемо лад.
- **Архів (431 МБ) існує в одному екземплярі.** Якщо він цінний — винести в
  окремий приватний репозиторій зі своєю зачисткою секретів.
