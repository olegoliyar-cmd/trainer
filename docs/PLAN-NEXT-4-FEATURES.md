## БЛОК 1. РОЗБОРИ 2.1 — кілька скрінів + відкриття завершеного розбору
**Найдешевше, найшвидша цінність. Робити першим.**

**Біль:** (а) тренер хоче слати КІЛЬКА розмічених скрінів на один розбір (нижня точка присіду,
верхня, згин, розгин…), кожен зі своєю розміткою; (б) після надсилання розбір «закривається» —
тренер більше не може в нього зайти й подивитись.

**Зміни моделі:**
- `form_check_requests.response_images jsonb` — МАСИВ шляхів `["tid/cid/a.jpg", ...]`.
  Зворотна сумісність: читати старий `response_image_path` як `[path]`, якщо масив порожній.
  (Колонку `response_image_path` НЕ дропати — легасі рядки.)
- retention-крон `formcheck-cleanup` — оновити: чистити ВСІ шляхи з `response_images` теж.

**Адмінка (`renderFormChecks` / композер):**
- «📷 Кадр + розмітка» → після `annotSave` **додає** скрін у список (не замінює).
  `FC_COMPOSE[id].imageBlobs = []` (масив), прев'ю-стрічка з мініатюрами + ✕ на кожній.
- `submitReview`: аплоуд усіх блобів → `response_images` масив.
- **Завершений розбір відкривається:** done-карта стає клікабельною → повний вигляд:
  відео (живе 7 днів після перегляду клієнтом — саме тому тренер має доступ), галерея скрінів,
  голосове, текст. Кнопка **«Доповнити розбір»** → відкриває композер на цьому ж запиті
  (додає нові скріни/голос/текст до наявних; `formcheck-review` робить merge, не replace).
- Стан «медіа прибрано» (після retention) — показувати текст + плашку «медіа прибрано за давністю».

**Клієнт (гілка «Розбори»):** галерея замість одного `<img>` — горизонтальна стрічка/свайп,
тап → зум (наявний `openFcrZoom` розширити на масив + стрілки next/prev).

## БЛОК 2. АВТОМАТИЗАЦІЯ ГРАФІКА ТРЕНУВАНЬ (Telegram)
**Середнє. Дає найбільший retention-ефект (дисципліна + контроль тренера).**

**Сценарій (з ТЗ):**
1. Клієнт має графік, напр. Пн/Ср/Пт (`clients.train_days` jsonb `["mon","wed","fri"]`, задає тренер).
2. **Ранок тренувального дня** → тренеру в TG: «Сьогодні тренування у Петі».
3. **18:00**, якщо тренування ще не залоговане і клієнт не відповів →
   клієнту в TG з **інлайн-кнопками**: «У тебе сьогодні тренування. Плануєш іти?» → `✅ Так` / `❌ Ні`.
4. Відповідь фіксуємо. Якщо не відповів — просто чекаємо.
5. **21:00**, якщо тренування так і не відбулося → тренеру: «Петя не пішов на тренування.
   Відповідь клієнта: {Так/Ні/не відповів}. Що сталося?»
   Якщо відбулося — тихо, все ок (вже є сповіщення про тренування).

**Модель:** `training_intents(id, trainer_id, client_id, date, answer text null, asked_at, answered_at)`
(unique client_id+date) — щоб не питати двічі й знати відповідь у вечірньому контролі.

**⚠️ ТЕХ-БЛОКЕР:** `telegram-webhook` зараз обробляє лише `message`. Треба додати
**`callback_query`** (натиск інлайн-кнопки) → `answerCallbackQuery` + запис відповіді + редагування
повідомлення («Записав: ідеш ✅»). Це ж потрібно Блоку 3 (підтвердження зустрічей).
→ `setWebhook` вже стоїть; додати `allowed_updates:["message","callback_query"]`.

**Крони:** розширити `daily-automations` новими режимами body `{run:"trainday_am"|"trainday_18"|"trainday_21"}`
+ 3 cron-джоби (05:05 вже є ранковий — можна вшити туди; 15:00 UTC = 18:00 Києва; 18:00 UTC = 21:00 Києва).

## БЛОК 3. КАЛЕНДАР / ЗУСТРІЧІ (дзвінки тренер↔клієнт)
**Середнє-велике. Нова сутність в обох аппах.**

**Модель:** `meetings(id, trainer_id, client_id, starts_at timestamptz, duration_min int default 30,
kind text 'online'|'gym', link text, note text, status 'planned'|'confirmed'|'declined'|'done'|'cancelled', created_at)`

**Тренер (адмінка):** новий розділ «Календар» у сайдбарі (список найближчих + тижнева сітка) +
кнопка «Запланувати зустріч» у картці клієнта. Поля: дата/час, тривалість, тип, нотатка.

**Посилання на дзвінок:** Google Meet API вимагає OAuth + Calendar API (важко, окремий трек).
**v1:** авто-генерація **Jitsi**-лінка `https://meet.jit.si/traineros-<uuid>` — миттєво, без авторизації,
працює в браузері й моб. + поле «своє посилання» (Zoom/Meet), якщо тренер хоче своє.
**v2 (пізніше):** Google Calendar OAuth → справжній Meet + подія в календарі обох.

**Клієнт:** картка «Найближча зустріч» на хабі + екран зустрічей; кнопка «Приєднатися» (лінк).
**TG-сповіщення:** при створенні (з інлайн-кнопками `✅ Підтверджую` / `❌ Не можу` → callback_query,
див. блок 2), нагадування **за 24 год** і **за 1 год** (крон, маркери в `meetings`).

## БЛОК 4. ЩОДЕННИЙ ЗВІТ (КВІЗ) + ТИЖНЕВИЙ/МІСЯЧНИЙ ЗВІТ  ⭐ найбільша ставка
**Найбільший блок. Це те, що робить сервіс не «щоденником тренувань», а системою ведення.**

**Ідея користувача:** тренування — лише одна складова результату. Клієнт щодня заповнює короткий
звіт (кроки/харчування/сон/режим/відновлення), з цього збирається тижневий і місячний звіт.
Коли клієнт каже «щось не росте» — тренер показує: «ти виконав 30% плану, ходив лише в зал».

### 4.1 Ключове рішення: КОНФІГУРОВАНИЙ чек-лист (не хардкод!)
Шаблон користувача (нижче) — під турніки. Треба, щоб той самий рушій обслуговував зал/дім/будь-що.
→ **Конструктор пунктів** на рівні тренера (шаблон) + призначення клієнту (можна перевизначити).

**Модель:**
- `clients.report_config jsonb` (або `trainers.report_template` + override на клієнті):
```json
{"items":[
 {"key":"training","label":"Тренування за планом","type":"bool","days":["mon","wed","fri"],"icon":"🏋️"},
 {"key":"steps","label":"Кроки","type":"choice","options":[{"v":0,"l":"<5к"},{"v":5000,"l":"5к"},{"v":10000,"l":"10к ✅"},{"v":15000,"l":"15к+"}],"goal":10000,"icon":"👟"},
 {"key":"nutrition","label":"Тримався плану харчування (БЖВ)","type":"bool","icon":"🍽"},
 {"key":"walk_after_meal","label":"Активність після їди (5-10 хв)","type":"bool","icon":"🚶"},
 {"key":"sleep_time","label":"Ліг спати у свій час","type":"bool","icon":"😴"},
 {"key":"meal_schedule","label":"Їв за графіком","type":"bool","icon":"⏰"},
 {"key":"body_scan","label":"15 хв без телефону + сканування тіла","type":"bool","weeklyGoal":3,"icon":"🧘"},
 {"key":"mood","label":"Самопочуття","type":"scale","min":1,"max":5,"icon":"⚡"}
]}
```
Типи: `bool` (Так/Ні), `choice` (варіанти тапом), `scale` (1-5), опційно `text`/`voice` (v2).
`days` — пункт показується лише в ці дні. `weeklyGoal` — ціль на тиждень (для скорингу).

- `daily_reports(id, trainer_id, client_id, date, answers jsonb, score int, created_at)` unique(client_id,date).
  `score` = % виконаних пунктів дня (для швидких графіків).

### 4.2 Доставка (квіз)
- **Крон 19:30 Києва (16:30 UTC)** → клієнту в TG: коротке нагадування ЧОМУ це важливо +
  **інлайн web_app кнопка** «Заповнити звіт (1 хв)» → відкриває Mini App **одразу на екрані звіту**
  (deep-link: `?screen=report` або `#report` — клієнтський роутер має це вміти).
- Якщо не заповнив — 1 нагадування о 21:30. Не спамити.

### 4.3 Клієнт: екран-квіз
- Повноекранний, **одне питання = один тап**, авто-перехід далі, прогрес-бар (як онбординг).
- Наприкінці — саммарі дня («4/6 виконано») + мотиваційний рядок. Зберігає через
  `client-api` екшн `report.submit` (upsert за датою).
- Вхід також вручну: картка на хабі «Звіт за сьогодні» (якщо ще не заповнено).

### 4.4 Тренер: вкладка «Звіти» в картці клієнта
- **День:** що виконано/не виконано (чек-лист із галочками).
- **Тиждень:** таблиця пункт×день (7 колонок) із ✅/❌ + % по кожному пункту + загальний score.
- **Місяць / 2-3 тижні:** графік динаміки score + топ-провали («кроки 30%, сон 40%»).
- Це і є той аргумент для розмови «чому не росте».
- Сповіщення тренеру про заповнений звіт — НЕ щодня (спам), а зведення в KPI + бейдж на вкладці.

### 4.5 Підсумок тижня (неділя)
- Клієнту в неділю: 3 рядки (що вдалось / що провалилось / що заважало) — текст АБО **голосове**
  (перевикористати наявний пайп чек-інів: `telegram-webhook` вже приймає голос → Whisper → саммарі).
- Тренеру — тижневий звіт із цим підсумком.

### 4.6 ШАБЛОН-ЕТАЛОН (від користувача, збережено дослівно — база для дефолтного конфігу)
```
ЗАВДАННЯ НА ТИЖДЕНЬ
Ці завдання обовʼязкові. Вони не замінюють програму і харчування — вони забезпечують результат.
Важливо: не виконав — так і пишеш. Головне не пропускати 2 дні підряд.

1. Тренування турніки (силове) — Пн/Ср/Пт. Після коротко відписати, як пройшло і самопочуття.
2. Щоденна активність — 10 000 кроків. Кожен день без винятків.
3. Щоденний звіт (по харчуванню, план БЖВ) + активність після прийому їжі (5-10 хв). Щовечора: що їв + самопочуття.
4. Режим: час сну (лягати в один час 7 днів) + графік харчування (їсти в один час).
5. Контакт з тілом (3 рази/тиждень): 15 хв перед сном без телефону + сканування тіла (пройтись «сканером», відчути зажими, розслабитись).
6. Якість тренувань: фіксувати вправи / підходи / повтори / вагу.
Підсумок тижня (неділя), 3 рядки: що вдалось / що провалилось / що заважало.
```
→ Це дефолтний шаблон «Турніки». Зробити ще **«Зал»** (тренування 3-4×/тиж, кроки, БЖВ, сон, режим)
і дати тренеру редагувати пункти під себе.

## ЗАЛЕЖНОСТІ (важливо для порядку)
- **`callback_query` у `telegram-webhook`** — спільний блокер для Блоків 2 і 3. Зробити ОДИН раз на початку.
- **Deep-link на екран у Mini App** (`?screen=report`) — потрібен Блоку 4. Перевірити, чи клієнтський
  роутер уміє стартувати не з хаба.
- **AI-ключі** (OPENAI/ANTHROPIC) — оживлять голосові чек-іни + підсумок тижня голосом + AI-ввід їжі.

## РЕКОМЕНДОВАНИЙ ПОРЯДОК
1. Блок 1 (Розбори 2.1) — швидко, користувач чекає.
2. `callback_query` інфра + Блок 2 (графік тренувань).
3. Блок 4 (щоденний звіт) — найбільша цінність, найбільше роботи.
4. Блок 3 (календар/зустрічі).
